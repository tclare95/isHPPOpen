# OpenSpec planning for the isHPPOpen suite

This repository is the canonical OpenSpec planning home for the web app, scraper and predictor. The source code, tests, CI and release procedures still belong to their individual repositories.

- `config.yaml` — default `spec-driven` workflow and suite constraints.
- `changes/<change-name>/` — proposed changes, each with a proposal, capability deltas, design and tracked tasks.
- `specs/<capability>/spec.md` — current requirements after changes are implemented and archived.

**First planned change:** [audit-web-engineering-standards](changes/audit-web-engineering-standards/proposal.md). Its code tasks are intentionally unchecked; adding the specification does not implement the fixes.

## Using the OpenSpec CLI

Install the current OpenSpec CLI locally following [OpenSpec's installation instructions](https://github.com/Fission-AI/OpenSpec). In the web repository, use `openspec list`, `openspec status --change audit-web-engineering-standards` and `openspec validate audit-web-engineering-standards --strict` to inspect this change. Use the OpenSpec Codex integration generated by `openspec init` / `openspec update` in your local workspace; review any generated files before committing them. The GitHub connector added the tracked planning artifacts but has **not** run the local CLI initialization or installed Codex skills.

When implementing, work on the application change in a separate branch and PR. Do not mark tasks done in the documentation-only onboarding PR. Update tracked tasks as work is verified, and archive only after implementation and review.

Cross-repository changes are defined here with a shared descriptive change name. Link each affected repository's issues and implementation PRs to the canonical change. The scraper and predictor retain their own production deployment approvals; the web repository may deploy on main merge.
